## Reporting a Vulnerability

This repository contains a **documentation methodology**, not executable code. However, we take vulnerabilities in the methodology, templates, or documentation seriously.

### What to report

- Errors in legal references (wrong articles, outdated laws)
- Incorrect MITRE ATT&CK mappings (wrong tactic/technique IDs)
- CVSS 4.0 scoring calculation errors
- Ambiguous or misleading language that could be misinterpreted as facilitating harm
- Broken URLs or references to unavailable sources

### How to report

1. **Do NOT open a public issue** for sensitive security concerns.
2. Email the maintainer at the address listed in the commit history, or
3. Open a **draft security advisory** via GitHub's "Report a vulnerability" feature (if the repository is on GitHub).

You can expect:
- Acknowledgment within **48 hours**
- A resolution or mitigation plan within **7 business days**
- Credit in the release notes if the finding is accepted

### Out of scope

- Vulnerabilities in third-party tools used with this methodology
- Reports about the Clínica Dávila case study itself (it is a fictional applied example)

## Responsible Disclosure

We ask that you give us reasonable time to address any issue before publicly disclosing it. We will do the same for you — any issue we find in your work will be reported privately first.
